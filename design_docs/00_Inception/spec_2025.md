### Purpose
Desktop application to determine base salaries over time for Tunisia according to Tunisian state sectoral collective agreements (Conventions Collectives Sectorielles).

**Description (FR)**: Système qui détermine le Salaire de base sur une longue période de temps pour la Tunisie suivant les conventions de l'État tunisien.

## 📋 Key Features

### 1. Sectoral Joint Agreements Management (الاتفاقيات القطاعية)

#### Functionality
- **CRUD Operations**: Create, Read, Update, Delete sectoral agreements
- **Data Management**: Store agreement names and descriptions
- **Relationship Management**: Link agreements to salary tables and affairs

#### Data Structure
```typescript
interface SectorialJointAgreement {
  sectorialJointAgreementId: number;
  agreementName: string;
  description: string | null;
  salaryTables: SalaryTable[];
  affairs: Affair[];
}
```

#### Features
- List all sectoral agreements
- Create new agreements
- Update existing agreements
- Delete agreements (cascade deletes related data)
- Search and filter agreements

---

### 2. Salary Tables Management (جداول الأجور)

#### Functionality
- **Dynamic Salary Matrix**: Interactive spreadsheet-like interface
- **Category Management**: Configure professional categories
- **Degree Management**: Define professional degrees with age of work
- **Date Range Validation**: Set application periods for salary tables
- **Type Support**: Hourly or Monthly salary calculations

#### Data Structure
```typescript
interface SalaryTable {
  salaryTableId: number;
  numeroTable: string;
  type: string; // 'Horaire' | 'Mensuelle'
  consernedEmployee: string;
  beginningDateOfApplication: Date;
  endDateOfApplication: Date | null;
  degrees: {key: string, degree: number, ageOfWork: number}[];
  categories: {key: string, label: string}[];
  salaryTableCells: SalaryTableCell[];
  agreementId: number;
  agreement: SectorialJointAgreement;
}
```

#### Key Components
- **SalaryTableForm**: Form for creating/editing salary tables
- **SalaryTableSheet**: Interactive salary matrix with editable cells
- **SalaryTablesList**: Display all salary tables
- **SalaryTablesForGivenAgreement**: Filter tables by agreement
- **SalaryTableStructure**: Configure table structure (categories/degrees)
- **SalaryTableContext**: Context API for state management

#### Features
- Create salary table with custom structure
- Define professional categories and degrees
- Input salary values in matrix format
- Set validity periods (beginning/end dates)
- Link to specific sectoral agreements
- Real-time cell editing
- Auto-save functionality
- Filter by agreement

---

### 3. Affairs Management (القضايا)

#### Functionality
- **Case Tracking**: Track employee compensation cases/disputes
- **Work Period Recording**: Document employment duration
- **Professional Progression**: Track category and degree changes
- **Agreement Linking**: Associate affairs with specific agreements and salary tables
- **Salary Calculations**: Link to monthly salary calculations

#### Data Structure
```typescript
interface Affair {
  affairId: number;
  affairNumber: string;
  title: string;
  claimant: string;
  startDateOfWork: string;
  endDateOfWork: string;
  professionalCategoryAtBegining: string;
  professionalDegreeAtBegining: number;
  agreementId: number;
  agreement: SectorialJointAgreement;
  salaryTableId: number;
  salaryTable: SalaryTable;
  actualMonthSalaries: ActualMonthSalary[];
}
```

#### Features
- Create and manage employee affairs
- Record claimant information
- Track work period
- Document initial professional category and degree
- Link to applicable sectoral agreement
- Associate with relevant salary table
- Calculate monthly salaries based on progression

---

### 4. Database Architecture

#### Entities

##### SectorialJointAgreement
- Primary entity for labor agreements
- One-to-Many with SalaryTable
- One-to-Many with Affair
- Cascade operations enabled

##### SalaryTable
- Stores salary table configurations
- JSON fields for degrees and categories
- Many-to-One with SectorialJointAgreement
- One-to-Many with SalaryTableCell
- One-to-Many with Affair
- Cascade operations for cells

##### SalaryTableCell
- Individual salary values in the matrix
- Many-to-One with SalaryTable
- Stores: row, column, value

##### Affair
- Employee case/dispute tracking
- Many-to-One with SectorialJointAgreement
- Many-to-One with SalaryTable
- One-to-Many with ActualMonthSalary

##### ActualMonthSalary
- Monthly salary calculations
- Many-to-One with Affair
- Stores calculated salary for specific month

#### Database Features
- **SQLite**: Local file-based database (payroll.sqlite)
- **TypeORM**: ORM with entity decorators
- **Eager Loading**: Optimized queries with relations
- **Cascade Operations**: Automatic cleanup of related records
- **Foreign Keys**: Enforced relationships
- **ON DELETE CASCADE**: Automatic cleanup on deletion

## 🔄 Application Flow

### 1. Application Initialization

```
1. Electron main.ts starts
2. Initialize SQLite database (TypeORM)
3. Create database tables if not exist
4. Initialize services (Agreement, SalaryTable, Affair)
5. Register IPC handlers for communication
6. Create browser window (1200x1000)
7. Load React app from http://localhost:9000
8. Install Redux DevTools and React DevTools
```

### 2. IPC Communication

#### Main Process → Renderer Process
- Electron provides API through contextBridge
- IPC handlers registered for all CRUD operations
- Services handle business logic
- TypeORM manages database operations

```typescript
'fetch-agreements'

'create-agreement'

'delete-agreement'

'fetch-salary-tables-by-agreement-id'

'update-salary-table'
'delete-salary-table'

// Affairs
'fetch-affairs'
'fetch-affair-by-id'
'create-affair'
'update-affair'
'delete-affair'
```

#### Context API
- **SalaryTableContext**: Local state for salary table editing
  - Categories
  - Headers (degrees)
  - Salary table cells
  - Cell value updates

### 4. User Workflows

#### Workflow 1: Create Complete Payroll Structure
```
1. Create Sectoral Agreement
   └─> Navigate to /agreements
   └─> Click "New Agreement"
   └─> Fill form (name, description)
   └─> Submit → IPC → Service → Database

2. Create Salary Table
   └─> Navigate to /salary-tables
   └─> Click "New Salary Table"
   └─> Select Agreement
   └─> Define structure (categories, degrees)
   └─> Fill salary matrix
   └─> Set date range
   └─> Submit → IPC → Service → Database

3. Create Affair
   └─> Navigate to /affairs
   └─> Click "New Affair"
   └─> Enter affair details
   └─> Select Agreement and Salary Table
   └─> Set work period
   └─> Define initial category/degree
   └─> Submit → IPC → Service → Database
```

#### Workflow 2: Update Salary Table
```
1. Navigate to /salary-tables
2. Click on specific table
3. Edit in SalaryTableSheet component
4. Context updates local state
5. Save triggers IPC call
6. Service updates database
7. Redux state updates
8. UI refreshes
```

## 📝 Key Technical Decisions

### 1. Why Electron?
- Cross-platform desktop application
- Local database access (SQLite)
- Full control over UI/UX
- No server required
- Offline functionality

### 2. Why TypeORM?
- Type-safe database operations
- Active Record pattern
- Migrations support
- Multiple database support
- Decorators for clean code

### 3. Why Redux Toolkit?
- Simplified Redux setup
- Built-in async thunks
- Immutability with Immer
- Redux DevTools integration
- Type-safe state management

### 4. Why Context API for Salary Tables?
- Local state for specific component tree
- Avoid Redux boilerplate for UI-only state
- Better performance for frequent updates
- Simpler state management for form editing

### 5. Why SQLite?
- No server setup required
- File-based database
- Portable data
- ACID compliance
- Perfect for desktop apps
